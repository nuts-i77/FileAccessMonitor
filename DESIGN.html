アーキテクチャ概要

FileAccessMonitor は Windows サービスとして動作し、Windows セキュリティイベントログから SMB ファイルアクセスイベントを取得して REST API + SPA ダッシュボードで可視化するツールです。監視対象のファイルサーバー本体（既定ポート 8080）上で自己完結型 EXE として動作します。

    Svc["EventLogCollectorService\n(バックグラウンドワーカー)"]
    DB["SQLite\nAccessRecord"]
    API["ASP.NET Core 10\nREST API :8080"]
    SPA["SPA\nwwwroot/index.html"]

    Svc -->|IP解決| DNS
    Svc -->|INSERT| DB
    API -->|EF Core| DB
    Client -->|JWT Bearer| API
    API -->|静的ファイル配信| SPA
制約事項：SACL の適用とセキュリティイベントログへのアクセスはローカル実行が必要なため、サービスはファイルサーバー上で直接動作させる必要があります。開発 PC からのデプロイは、WinRM が使える場合は deploy-remote.ps1、使えない場合は UNC パス経由のファイルコピーと sc.exe（RPC）によるサービス制御で行います（後述）。

データモデル

AccessRecord

Idlong — 自動インクリメント主キー
FilePathstring MaxLength(2000) — フルパス（例: U:\share\foo.txt）
FileNamestring MaxLength(500) — ファイル名のみ
FolderPathstring MaxLength(2000) — 親ディレクトリ
UserNamestring MaxLength(200) — Windows アカウント（DOMAIN\user 形式）
AccessTypestring MaxLength(20) — "Read" | "Write" | "Delete"
AccessTimeDateTime UTC — イベント発生時刻
ClientIpstring? MaxLength(100) — ログオン／SMB セッションキャッシュからのリモート IP
ClientMachinestring? MaxLength(200) — DNS またはワークステーション名で解決したホスト名

インデックス（AccessDbContext）

HasIndex(r => r.FilePath)
HasIndex(r => r.FolderPath)
HasIndex(r => r.AccessTime)
HasIndex(r => r.UserName)
HasIndex(r => new { r.FilePath, r.AccessTime })

スキーママイグレーション

データベースは EnsureCreated() で作成されます。v2 で追加した ClientIp・ClientMachine 列は、起動時に pragma_table_info で存在を確認し、無い場合のみ ALTER TABLE … ADD COLUMN で追加されます（既存データを破壊しない非破壊的アップグレード）。

Identity テーブル

AccessDbContext は IdentityDbContext<ApplicationUser> を継承しています。ASP.NET Identity のテーブル（ユーザー、ロール、クレームなど）はアクセスログと同じ SQLite ファイル（C:\ProgramData\FileAccessMonitor\fileaccess.db）に共存します。

イベント処理パイプライン

EventLogCollectorService は以下の XPath で Windows セキュリティイベントログを購読します：

*[System[(EventID=4663) or (EventID=4659) or (EventID=4624) or (EventID=5140)]]

各イベントの役割

イベント ID用途処理内容
4663オブジェクトアクセス（読み取り／書き込み）AccessMask を解析してアクセス種別を判定し、監視対象パスのものを記録
4659削除目的のハンドル要求常に Delete として記録 — 現行 Windows での削除検知に重要
4624ログオンイベントログオンセッション ID → (IP, マシン名) を _logonCache にキャッシュ
5140ネットワーク共有アクセスユーザー名 → (IP, マシン名) を _smbSessionCache にキャッシュ

AccessMask の解析（イベント 4663）

0x10000           → Delete（削除）
0x2 / 0x4 / 0x40000002 → Write（書き込み）
0x1 / 0x80000000  → Read（読み取り）
その他             → スキップ（記録しない）

IP / マシン名の解決

実行時に2つのキャッシュを保持します：

  • _logonCache — ログオンセッション ID → (IP, マシン名)。起動時に過去30日分のイベントから事前ロード
  • _smbSessionCache — ユーザー名 → (IP, マシン名)。NetSessionEnum Win32 API で30秒ごとに更新

いずれのキャッシュでもマシン名が取得できない場合、DnsResolverService.TryResolve(ip) にフォールバックします。解決できない場合は ClientMachine に null が格納されます。

パスの正規化

イベントログのパスは NT デバイスパス形式（\Device\HarddiskVolume3\...）で届きます。起動時に BuildDeviceMap() が QueryDosDevice を呼び出して各ボリュームとドライブレターのマッピングを構築し、記録前にパスを変換します。

フィルタリング

  • $ で終わるアカウント名はスキップ（ExcludeSystemAccounts=true）
  • ExcludeProcessNames に指定されたプロセス名はスキップ（System, svchost.exe, SearchIndexer.exe）
  • ファイルパスが監視対象パスのいずれかで始まる必要がある（設定した eventTypes に含まれるアクセス種別のみ記録）

起動時プリロード

XPath: *[System[(EventID=4624 or EventID=5140 or EventID=4659)
        and TimeCreated[timediff(@SystemTime) <= 2592000000]]]

起動時に過去30日分のセキュリティイベントログを読み込んでキャッシュをウォームアップします。

サービス

EventLogCollectorService

IHostedService として登録されたコアのバックグラウンドワーカーです。詳細は上記「イベント処理パイプライン」を参照してください。

DnsResolverService

シングルトン。設定可能なプライベート DNS サーバーに対して UDP PTR 逆引きルックアップを行います。

SetDnsServer()実行時に DNS サーバーアドレスを更新（SettingsController の保存時に呼び出し）
GetDnsServer()現在の DNS サーバーアドレスを返す
TryResolve(ip)逆引きルックアップ。正引きキャッシュ1時間、否定キャッシュ5分。サーバー未設定またはルックアップ失敗時は null を返す

PTR クエリ例: 192.0.2.31 → 31.2.0.192.in-addr.arpa。生 UDP QTYPE=12 (PTR), QCLASS=IN, タイムアウト 1500ms。レスポンスの DNS ラベルポインタ圧縮にも対応。

SaclManagerService

シングルトン。監視対象パスの Windows SACL（監査 ACE）を管理します。

EnableAuditPolicy()auditpol /set /subcategory:"{0CCE921D-...}" を実行してファイルシステムオブジェクトアクセス監査を有効化
ApplySacl(path)FileSystemRights.ReadData|WriteData|AppendData|Delete, AuditFlags.Success, Everyone の監査ルールをパス配下に再帰適用。既存の Everyone ルールは置き換え（属性読み取り等は監査しないことで Security ログの肥大化を防ぐ）
RemoveSacl(path)Everyone の監査ルールをパス配下から再帰的に削除

RetentionService

シングルトン兼 IHostedService。設定された保持ポリシーの期限を超えた AccessRecord 行を定期的に削除します。

appsettings.json（EXE 内蔵・基本設定）

{
  "Kestrel": { "Endpoints": { "Http": { "Url": "http://0.0.0.0:8080" } } },
  "Jwt": {
    "Issuer": "FileAccessMonitor",
    "Audience": "FileAccessMonitor",
    "ExpiresHours": 24
  },
  "MonitoredPaths": [],
  "ExcludeSystemAccounts": true,
  "ExcludeProcessNames": ["System", "svchost.exe", "SearchIndexer.exe"]

Jwt:Key は通常指定しません。未指定（または 32 バイト未満・サンプル値）の場合、初回起動時にランダムな鍵を生成して C:\ProgramData\FileAccessMonitor\jwt.key（SYSTEM / Administrators のみ読み取り可）に保存します。

多言語対応（i18n）

フラットな JS 辞書方式。言語ファイルは wwwroot/lang/ja.js と wwwroot/lang/en.js に配置。それぞれ window.I18N_JA / window.I18N_EN を定義します。t(key) 関数がアクティブな言語辞書を参照し、data-i18n="key" 属性を持つ要素は applyI18n() で言語切替時に一括更新されます。

新しい i18n キーの追加方法

lang/ja.js と lang/en.js の両方に同じキー名で追加します。HTML では data-i18n="key"、JS では t('key') を使用します。テンプレート補間には {n}、{u}、{p} などのプレースホルダーを使い、呼び出し側で文字列置換します。

デプロイ

デプロイ先

サーバー監視対象のファイルサーバー（以下 FILESERVER）
サービス名FileAccessMonitor
インストール先C:\FileAccessMonitor\publish\
ポート8080 (http)
データベースC:\ProgramData\FileAccessMonitor\fileaccess.db
ユーザー設定C:\ProgramData\FileAccessMonitor\settings.json

ビルドスクリプト（build.ps1）

dotnet publish -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true -o ./publish

WinRM が使える場合

.\deploy-remote.ps1 -ServerIP FILESERVER

手動デプロイ手順（WinRM が使えない場合）

# 1. ビルド（リポジトリのルートで実行）
.\build.ps1

# 2. サービス停止
sc.exe \\FILESERVER stop FileAccessMonitor

# 3. EXE のロックが解放されるまで待機（プロセスが終了したことを確認）

# 4. ファイルコピー
#    EXE は実行中はロックされるため、停止後にコピーすること
Get-ChildItem -Path .\publish -Recurse -File | ForEach-Object {
    $dst = $_.FullName.Replace(
        (Resolve-Path .\publish).Path,
        "\\FILESERVER\C$\FileAccessMonitor\publish"
    )
    New-Item -ItemType Directory -Path (Split-Path $dst) -Force | Out-Null
    Copy-Item $_.FullName $dst -Force
}

# 5. サービス起動
sc.exe \\FILESERVER start FileAccessMonitor
注意：Copy-Item -Recurse -Force は既存ファイルが更新されないことがある（タイムスタンプが変わらない場合）ため、ファイル単位のコピーループを使用してください。
確認方法：sc.exe \\FILESERVER qc FileAccessMonitor を実行するとサービスの実際のバイナリパスを確認できます。デプロイ先がずれていると思われる場合に使用してください。

認証・ロール

JWT Bearer 認証。トークンの有効期限は 24 時間（Jwt:ExpiresHours で変更可能）。2つのロール：

ロール権限
Viewer読み取り専用: ダッシュボード・統計・検索・最新アクセスログ・自分のパスワード変更
AdminViewer の全機能 + 設定管理・ユーザー管理・保持ポリシー・SACL 操作・他ユーザーのパスワードリセット

ユーザー管理は ASP.NET Identity によってアクセスログと同じ SQLite DB に保存されます。初回起動時に管理者アカウントが自動作成されます。追加アカウントは設定タブ → ユーザー管理から作成できます。
