## English

### Security fixes

- **Registration codes can no longer take over a registered agent.** Before, a registration code used with the name of an agent that was already registered replaced that agent's key: the real agent was cut off and records came from the new one. Now a code from **Issue registration code** registers only a server that is not registered yet. To register an agent again (for example after reinstalling the file server), use the new key button in that agent's row under **Settings → Agents**; that code registers only that agent. No code registers a server under the monitoring server's own name. A refused code is not used up, and the refusal is written to the operation log.
- **Failed sign-ins no longer lock the account for everyone.** Before, 5 wrong passwords from anywhere locked the account for 15 minutes, so anyone who could reach the web GUI could keep `admin` locked out. Now the failures count per user name and client address: 5 failures within 15 minutes pause that user's sign-in from that address only. An address with 20 failures for any names, and a name with 100 failures from any addresses, are paused as well. Unknown user names count too.
- **Signing out ends the token on the server.** Before, **Sign out** only removed the token from the browser, and a copy of it stayed valid for up to 24 hours. Now the server refuses that token after signing out (other sign-ins of the same user stay). The default sign-in lifetime (`Jwt:ExpiresHours`) is now 8 hours instead of 24.

### Improvements

- **Server filter**: a new switch under **Settings → Agents** leaves removed agents out of the server filter at the top right. Their records are kept and still shown under **All servers**. Off by default.

### Fixes

- **Unused files**: after opening a subfolder from the list, the browser's Back button now returns to the folder above (the result shown before is reused; **Search** scans again). The folder names of Linux paths were shown as the whole path; now only the last part is shown.

### Upgrading

- Update the monitoring server. Agents are unchanged; reinstalling an agent that keeps its `agent.json` needs no new code.
- If you set `Jwt:ExpiresHours` in `appsettings.Production.json`, that value is kept.
- Behind a reverse proxy, list it in `ReverseProxy:KnownProxies`, so that the sign-in limit counts the real client addresses. Without it, sign-ins through a proxy on another machine all count as that proxy's address; sign-ins from loopback are not counted per address.

## 日本語

### セキュリティの修正

- **登録コードで、登録済みのエージェントを乗っ取れないようにしました。** これまでは、すでに登録されているエージェントと同じ名前で登録コードを使うと、そのエージェントの鍵が入れ替わっていました。本物のエージェントはつながらなくなり、記録は新しい方から届いていました。今後、［登録コードを発行］のコードで登録できるのは、まだ登録されていないサーバーだけです。ファイルサーバーの再インストール後などにエージェントを登録し直す場合は、**設定 → エージェント** の一覧で、そのエージェントの行に追加した鍵のボタンからコードを発行します。そのコードは、そのエージェントの再登録にしか使えません。監視サーバー自身と同じ名前では、どのコードでも登録できません。拒否されたコードは消費されず、拒否したことは操作ログに残ります。
- **ログインの失敗で、アカウントがロックされないようにしました。** これまでは、どこからでも 5 回パスワードをまちがえるとアカウントが 15 分間ロックされたため、Web GUI に接続できる人なら誰でも `admin` を締め出し続けられました。今後は、ユーザー名と接続元アドレスの組み合わせごとに数えます。15 分以内に 5 回失敗すると、そのアドレスからそのユーザーでのログインだけを止めます。どのユーザー名でも合わせて 20 回失敗したアドレス、どのアドレスからでも合わせて 100 回失敗したユーザー名も止めます。存在しないユーザー名での失敗も数えます。
- **ログアウトすると、トークンをサーバー側でも無効にするようにしました。** これまでの［ログアウト］はブラウザーからトークンを消すだけで、コピーされたトークンは最長 24 時間使えました。今後は、ログアウトしたトークンをサーバーが拒否します（同じユーザーのほかのログインはそのままです）。ログインの有効期間の既定（`Jwt:ExpiresHours`）は、24 時間から 8 時間に短くしました。

### 改善

- **サーバーの絞り込み**: **設定 → エージェント** に、削除したエージェントを画面右上のサーバーの絞り込みに表示しないスイッチを追加しました。削除したエージェントの記録は残り、［全サーバー］では引き続き表示されます。既定はオフです。

### 修正

- **未使用ファイル**: 一覧からサブフォルダを開いたあと、ブラウザーの戻るボタンで上のフォルダに戻れるようにしました（前に表示した結果を使います。［検索］を押すと改めてスキャンします）。また、Linux のパスでは、フォルダ名の欄にパス全体が表示されていました。最後の部分だけを表示するように直しました。

### 更新時の注意

- 更新が必要なのは監視サーバーです。エージェントに変更はありません。`agent.json` を残したままエージェントを再インストールする場合は、新しいコードは不要です。
- `appsettings.Production.json` で `Jwt:ExpiresHours` を指定している場合は、その値がそのまま使われます。
- リバースプロキシの背後で使う場合は、`ReverseProxy:KnownProxies` にプロキシを登録してください。ログインの回数制限が、本来の接続元アドレスで数えるようになります。登録しないと、別のマシンのプロキシ経由のログインは、すべてプロキシのアドレスとして数えます（ループバックからの接続は、アドレスごとには数えません）。
