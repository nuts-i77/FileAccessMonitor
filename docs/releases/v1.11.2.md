## English

An audit-trail test of every kind of file operation on Windows (local NTFS) and on Linux (Samba, from Windows and from smbclient) found the gaps below. All of them are fixed.

### Fixes: accesses that were not recorded

- **A newly monitored folder was not monitored until the agent was idle.** Agents and the monitoring server's own collector fetched the monitored folders only with a heartbeat, which was sent only after a minute without anything else to send. On a busy server, accesses to a folder added in the GUI were dropped until then. The settings version now comes with every answer to a batch, a heartbeat is sent every minute even while batches go, and the settings are fetched again 3 seconds after setting up or removing a folder's auditing.
- **Windows: creating an empty file and emptying a file were not recorded.** The Security log has nothing for them (no data is written), for example **New → Text Document** in Explorer. They are now taken from the USN journal: a create or truncation that no logged write explains within 30 seconds is recorded with the user **(unknown)**. To record who it was, turn on **Settings → Recording → Also audit file opens** (Handle Manipulation success auditing; about twice the Security log events).
- **Saves through a temporary name left the new file unrecorded.** A file renamed from an excluded name (such as `x.tmp` or `~WRD0001.tmp`) to a recorded one is now recorded as a write of that name, on Windows (with the USN journal) and on Linux.

### Fixes: records of the wrong kind

- **Linux: an Office save over SMB looked like the document being renamed away** ("doc.docx → ~WRL0001.tmp"). It is now one write of the document, as on Windows.
- **Windows: a save through ReplaceFile (File.Replace, many editors) left a refused Delete,** because Windows refuses the first DELETE request and grants the second. A refused delete followed within 2 seconds by the same user's successful DELETE access to the same file is no longer recorded.
- **Windows: a rename that only changes the case of a name was recorded as a Write.** It is a Rename now.
- **One save left two or three writes.** Writes of one file by one user within 2 seconds are recorded once, on Windows and on Linux.
- **Windows: with the USN journal, every record waited up to 10 seconds** after the folders of a volume were removed (the volume kept counting as "not read up to now").

### Other

- `SHA256SUMS.txt` has Unix line ends, so `sha256sum -c --ignore-missing SHA256SUMS.txt` works on Linux as it is.
- README: what is not recorded (alternate data streams), what a Write means on Linux (opened for writing: a timestamp change through such an open is a Write), and when copies record a Permission change.

### Upgrading

- Update the monitoring server and the agents (Windows and Linux). An agent of 1.11.1 or earlier keeps working with this server, but gets folder changes only with its heartbeat, as before.
- "Also audit file opens" is off by default. Turning it on changes the audit policy of that server (Handle Manipulation, success); turning it off again restores it.

## 日本語

Windows（ローカルの NTFS）と Linux（Samba、Windows と smbclient から）で、あらゆる種類のファイル操作の記録を突き合わせる試験を行い、見つかった次の問題をすべて直しました。

### 修正: 記録されていなかったアクセス

- **追加した監視フォルダが、エージェントの手が空くまで監視されませんでした。** エージェントと監視サーバー自身の収集サービスは、監視フォルダの設定をハートビートのときにだけ取りに行き、ハートビートは 1 分間ほかに送るものがないときにだけ送っていました。忙しいサーバーでは、それまで GUI で追加したフォルダへのアクセスが捨てられていました。記録の送信への応答に設定の版を含め、送信が続いていても 1 分ごとにハートビートを送り、フォルダの監査の設定・解除の 3 秒後に設定を取り直すようにしました。
- **Windows: 空のファイルの作成と、ファイルを空にする操作が記録されていませんでした。** データを書かないため、Security ログに何も残りません（エクスプローラーの **新規作成 → テキスト ドキュメント** など）。USN ジャーナルから取り、30 秒以内にログの書き込みで説明できない作成・切り詰めを、ユーザー **(unknown)** で記録するようにしました。誰が行ったかまで記録するには、**設定 → 記録 → ファイルを開く操作も監査する** をオンにします（ハンドルの操作の成功の監査。Security ログの量がおよそ 2 倍になります）。
- **一時的な名前を経由した保存で、新しいファイルが記録されていませんでした。** 除外される名前（`x.tmp`、`~WRD0001.tmp` など）から記録される名前への名前変更を、変更後の名前への書き込みとして記録するようにしました（Windows は USN ジャーナルがある場合。Linux も同様）。

### 修正: 種類が正しくなかった記録

- **Linux: SMB 経由の Office の保存が、文書が別名に変更されたように記録されていました**（「doc.docx → ~WRL0001.tmp」）。Windows と同じく、文書への書き込み 1 件にしました。
- **Windows: ReplaceFile（File.Replace、多くのエディター）での保存で、拒否された削除が残っていました。** Windows は最初の削除権限の要求を拒否し、2 回目に許可するためです。同じユーザーが 2 秒以内に同じファイルの削除権限を得た場合、その拒否は記録しないようにしました。
- **Windows: 大文字と小文字だけを変えた名前変更が、書き込みとして記録されていました。** 名前変更として記録するようにしました。
- **1 回の保存で、書き込みが 2〜3 件残っていました。** 同じユーザーによる同じファイルへの書き込みは、2 秒以内なら 1 件にまとめるようにしました（Windows・Linux とも）。
- **Windows: あるボリュームの監視フォルダをすべて外すと、USN ジャーナルを使う記録がすべて最大 10 秒待たされていました**（そのボリュームが「読み終えていない」扱いのまま残っていたため）。

### その他

- `SHA256SUMS.txt` の改行を Unix 形式にしました。Linux で `sha256sum -c --ignore-missing SHA256SUMS.txt` がそのまま使えます。
- README: 記録しないもの（代替データストリーム）、Linux の書き込みの意味（書き込み用に開いたこと。そのように開いて更新日時を変えた場合も書き込み）、コピーで権限変更が記録される場合を追記しました。

### 更新時の注意

- 監視サーバーとエージェント（Windows・Linux）を更新してください。1.11.1 以前のエージェントもこのサーバーで動きますが、フォルダの変更を受け取るのは従来どおりハートビートのときだけです。
- 「ファイルを開く操作も監査する」は既定でオフです。オンにすると、そのサーバーの監査ポリシー（ハンドルの操作の成功）を変更します。オフに戻すと元に戻します。
