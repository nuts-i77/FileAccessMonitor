## English

### New: setup wizard

After the first sign-in, a wizard takes you through what used to be manual steps:

1. Change the generated admin password (only while it is still the one from `initial-admin-password.txt`).
2. Pick the file server: this monitoring server or an agent's (when there are agents).
3. Add the first monitored folder; its auditing is set up right away.
4. Enlarge the Security log (Windows; 1 GB is recommended). The wizard shows the current size and use, and warns when the log is not set to overwrite the oldest events.
5. Open or save a file and see its record arrive. Before waiting, it says when auditing is off on that server or when users are excluded from recording.

It opens by itself for an Admin while no folder is monitored, and from **Settings → Setup wizard** at any time. **Later** closes it for this browser session; **Do not show again** and **Finish** for good.

### New: Security log in Settings

Each Windows server has its own Security log: this monitoring server and every Windows agent's server. **Settings → Security log** (under the per-server settings) shows the log of the server picked there, with its maximum size, what is in use and how it is kept, and sets its maximum size. The collector or the agent of that server does it, so an agent's server is set from the monitoring server too. That needs a Windows agent of 1.12 or later; an older one is told to update. Linux servers have no such card.

### Improvements

- **Dashboard:** the Access Types card shows every type, also with 0, and explains each one when you point at it. A type without records no longer looks like a type that is not recorded.
- **"(unknown)" users** (an empty file created, or a file emptied by overwriting it, which Windows does not log; see 1.11.2) have a link to the README passage that explains them.
- **CSV exports:**
  - Lines end in CRLF on every server OS.
  - When the 200,000-row limit (search) or another limit cut the result, the GUI says so.
  - At most two exports run at a time.
  - A search export is recorded in the audit log also when the download breaks off, with the rows sent.

### Fixes

- **Linux monitoring server:** API messages (errors and confirmations) came in English even when the GUI was in Japanese.

### Upgrading

- Update the monitoring server first, then the agents. Agents of 1.11 keep working with this server; only setting their Security log from the wizard needs 1.12.
- An existing installation with monitored folders does not open the wizard by itself.

## 日本語

### 新機能: 導入ウィザード

初回ログインの後、これまで手作業だった手順を、ウィザードが順に案内します。

1. 自動生成された admin のパスワードを変更します（`initial-admin-password.txt` のパスワードのままの場合だけ）。
2. ファイルサーバーを選びます。この監視サーバーか、エージェントのサーバーです（エージェントがある場合）。
3. 最初の監視フォルダを追加します。監査はその場で設定されます。
4. Security ログを拡張します（Windows。推奨は 1 GB）。現在のサイズと使用量を表示し、古いイベントから上書きする設定になっていなければ警告します。
5. ファイルを開くか保存して、その記録が届くことを確かめます。待つ前に、そのサーバーで監査がオフの場合と、記録から除外されたユーザーがいる場合は、その旨を表示します。

管理者がログインしたとき、監視フォルダが 1 つもなければ自動で開きます。**設定 → 導入ウィザード** からはいつでも開けます。**あとで** はそのブラウザーのセッションの間だけ閉じ、**今後表示しない** と **完了** は以後自動では開かなくなります。

### 新機能: 設定画面の Security ログ

Security ログは Windows のサーバーごとにあります（この監視サーバーと、各 Windows エージェントのサーバー）。**設定 → Security ログ**（サーバーごとの設定の中）に、そこで選んだサーバーの Security ログの上限、使用量、保持方式を表示し、上限を変更できます。読み取りと設定はそのサーバーのコレクターまたはエージェントが行うので、エージェントのサーバーも監視サーバーから設定できます。これには 1.12 以降の Windows エージェントが必要で、古いエージェントの場合は更新するよう表示します。Linux のサーバーでは、この欄は表示しません。

### 改善

- **ダッシュボード:** アクセス種別のカードに、0 件の種別も含めてすべての種別を表示します。マウスを乗せると、それぞれの意味を表示します。記録のない種別が、記録されない種別のように見えなくなります。
- **ユーザー「(unknown)」の記録**（Windows のログに残らない、空のファイルの作成や上書きで空にする操作。1.11.2 を参照）に、説明が書かれた README の箇所へのリンクを付けました。
- **CSV 出力:**
  - どの OS の監視サーバーでも、改行を CRLF にしました。
  - 20 万件（検索）などの上限で打ち切った場合は、画面に表示します。
  - 同時に実行できる出力は 2 つまでにしました。
  - 検索の CSV 出力は、ダウンロードが途中で切れた場合も、送った件数とともに操作ログに記録します。

### 修正

- **Linux の監視サーバー:** 画面が日本語でも、API のメッセージ（エラーや確認のメッセージ）が英語で返っていました。

### 更新時の注意

- 監視サーバーを先に、エージェントを後に更新してください。1.11 のエージェントもこのサーバーで動きます。ウィザードからエージェントのサーバーの Security ログを設定する場合だけ、1.12 が必要です。
- 監視フォルダがある既存の環境では、更新してもウィザードは自動では開きません。
