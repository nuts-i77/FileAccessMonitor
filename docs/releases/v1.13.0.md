## English

### New

- **Backup and restore of the data folder.** Settings, keys and the database are saved with each file's permissions, so the keys stay readable by the services and administrators only. See [Backup and restore](../backup.md).
  - **A daily backup**, set up by the installer and the rpm/deb packages (2:00, keeping the last 7). Change the time, the number and the folder (another disk or a share) with `backup-schedule`; it is a Task Scheduler task or a systemd timer.
  - Commands (as an administrator or root): `backup`, `backups`, and `restore <name>`, which stops the services, puts the backup in place and starts them again. What was there before is kept as a backup of its own, so a restore can be undone.
  - **Before each upgrade**, the installer and the rpm/deb packages make a backup and keep the last 3. To go back after a failed update, install the earlier version, then restore that backup.
  - A restore is written to the operation log, and tamper detection verifies the restored records as before.
  - **Settings → Backup** shows the daily backup and the backups, warns when the last one is more than 2 days old, and shows the commands to copy. The web GUI cannot make or restore backups: it runs without privileges, and a stolen sign-in must not be able to copy the keys elsewhere.

### Changes

- **Settings are split into pages.** A menu on the left opens one page at a time: per server, Monitored folders, Recording rules and Security log; for all servers, Agents, Notifications, Scheduled report, Tamper detection, Users, Retention and DNS, Backup, App and connection, and Operation log. The server to set up is picked above the menu. The page last opened is opened again next time.
- **Shorter explanations.** Each setting shows one line about what it does. Notes and per-OS steps open with **Details**.
- **One Totals tab.** By file, by folder and by user are now one tab, switched with the buttons at its top. Links that open these lists directly (`#files`, `#folders`, `#users`) still work.
- **A shorter README.** The README now covers what the tool does, the requirements and the first setup. The details moved to separate pages under `docs/` (installation details, agents, the Linux monitoring server, the web GUI, security, configuration, how it works, comparison, uninstall), linked from the README. The **?** next to the user "(unknown)" opens the limitations in the new place.

### Fixes

- After a click on a top tab, the address lost the tab (`#recent` and so on), so reloading the page went back to the dashboard. It now stays on the tab.
- **Show the initial admin password** at the end of the Windows installer could not open the file (it is readable by administrators only since 1.11, and Notepad ran without elevation). It now opens.

### Upgrading

- Only the monitoring server changed. Agents do not need an update.
- The upgrade to 1.13 already makes a backup before it changes anything: it needs free space of about the size of `fileaccess.db` on the drive of the data folder.
- The upgrade also sets up the daily backup (Windows: unless its task is unticked). Stop it with `backup-schedule --off`.

## 日本語

### 新機能

- **データフォルダのバックアップと復元。** 設定・鍵・データベースを各ファイルの権限ごと保存するため、鍵は引き続きサービスと管理者だけが読めます。[バックアップと復元](../backup.ja.md) を参照してください。
  - **毎日のバックアップ**: インストーラーと rpm・deb パッケージが設定します（2:00、直近の 7 個を残す）。時刻、残す数、保存先（別のディスクや共有フォルダ）は `backup-schedule` で変更します。実体はタスク スケジューラのタスク、または systemd のタイマーです。
  - コマンド（管理者または root）: `backup`、`backups`、`restore <名前>`。`restore` はサービスを止めて、バックアップを戻し、サービスを再開します。復元の直前の状態もバックアップとして残るため、復元を取り消せます。
  - **更新のたびに**、インストーラーと rpm・deb パッケージが更新前のバックアップを作り、直近の 3 個を残します。更新に失敗したときは、以前のバージョンを入れ直してから、そのバックアップを復元します。
  - 復元は操作ログに記録し、改ざん検知は復元した記録をこれまでどおり検証します。
  - **設定 → バックアップ** に、毎日のバックアップの設定とバックアップの一覧を表示し、最後のバックアップが 2 日以上前なら警告します。実行するコマンドもコピーできる形で表示します。Web GUI からはバックアップの作成や復元はできません。Web GUI は権限のないアカウントで動いており、ログイン情報が盗まれても鍵を別の場所へコピーされないようにするためです。

### 変更

- **設定をページに分けました。** 左のメニューで選んだ項目だけを表示します。サーバーごとの設定は「監視フォルダ」「記録ルール」「Security ログ」、全体の設定は「エージェント」「通知」「定期レポート」「改ざん検知」「ユーザー」「データ保持と DNS」「バックアップ」「アプリと接続」「操作ログ」です。設定するサーバーは、メニューの上で選びます。最後に開いたページを、次回も開きます。
- **説明を短くしました。** 各項目には、何をするかを 1 行だけ表示します。注意点や OS ごとの手順は［詳しく］で開きます。
- **集計を 1 つのタブにまとめました。** ファイル別・フォルダ別・ユーザー別は 1 つのタブになり、上部のボタンで切り替えます。これらの一覧を直接開くリンク（`#files`、`#folders`、`#users`）はそのまま使えます。
- **README を短くしました。** README には、できること、必要環境、最初の導入だけを書き、詳しい説明は `docs/` の別ページ（インストールの詳細、エージェント、Linux の監視サーバー、Web GUI、セキュリティ、設定、仕組み、他のツールとの比較、アンインストール）に移して、README からリンクしました。ユーザー「(unknown)」の横の **？** は、移動先の制限事項を開きます。

### 修正

- 上のタブを押すと、アドレスからタブ（`#recent` など）が消え、ページを再読み込みするとダッシュボードに戻っていました。開いていたタブのままになるようにしました。
- Windows のインストーラーの完了画面の **初期パスワードを表示** で、ファイルを開けませんでした（1.11 からこのファイルは管理者だけが読めるようになりましたが、メモ帳を管理者の権限なしで開いていたため）。開けるようにしました。

### 更新時の注意

- 変更は監視サーバーだけです。エージェントは更新しなくても構いません。
- 1.13 への更新から、更新前のバックアップを作ります。データフォルダのドライブに、`fileaccess.db` と同じくらいの空き容量が必要です。
- 更新時に、毎日のバックアップも設定します（Windows では、そのタスクのチェックを外した場合を除く）。止めるには `backup-schedule --off` を実行します。
