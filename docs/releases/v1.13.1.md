## English

### New

- **Settings → Monitored folders shows the change journal of each folder's drive.** On Windows, creations and the new names of renamed or moved files are recorded only on a drive with a change journal (USN journal). Each folder now says whether its drive has one. For a FAT32, exFAT or network folder, the line says that it cannot have one.
- **Turn on a drive's change journal from the web GUI.** For a drive without one, **Turn on the change journal** creates the journal there. It is the same as `fsutil usn createjournal m=33554432 a=8388608`, run by the collector service or the agent.
  - It asks first, and the operation log records who turned it on, on which server and drive.
  - Only a drive shown without a journal can be turned on. A journal that exists is never changed (another program may have chosen its size), the size is fixed, and there is no way to turn a journal off from the web GUI.
  - The command is shown there too, ready to copy with the drive letter filled in, for turning it on at the server instead.
  - The setup wizard shows the same under the folder added in its **Folder** step, with **Turn on the change journal**.
- **A notice when a drive has no journal.** The bar at the top of every tab (for Admins) lists the servers and drives whose journal is off, and opens their monitored folders. The Monitored folders page shows the same at its top, with a button per drive.
- Windows agents show the journal state, and take **Turn on the change journal**, from 1.13.1.

### Changes

- **A journal turned on is read within a minute.** The collector looks at drives without a journal every minute (10 minutes before), so a journal an administrator creates is used without a restart. A drive's state is written to the service log when it changes, not at each look.
- **Clearer steps for the journal.** [Creations and renames on Windows](../install.md#create-and-renames-on-windows-usn-journal) now explains how to read the output of `fsutil usn queryjournal`, what the values of `fsutil usn createjournal` mean, what happens after it, and what to watch out for (do not run it on a drive that already has a journal; how to turn it off again). The log message for a drive without a journal and the explanation in the web GUI say the same.
- **ReFS is listed as supported.** Monitoring, the change journal and backups work on ReFS drives as on NTFS. This was tested on Windows Server 2025 with ReFS 3.14. The README, the installation details and the error for a backup folder that cannot keep permissions now mention ReFS.

### Upgrading

- Monitoring server: update to show the journal state.
- Windows agents: update for their folders to show the journal state and offer **Turn on the change journal** too. An agent of 1.13.0 keeps working, and its folders show no journal line.
- Linux agents do not need an update.

## 日本語

### 新機能

- **設定 → 監視フォルダ に、各フォルダのドライブの変更ジャーナルの状態を表示します。** Windows では、ファイルの作成と、名前変更・移動の後の名前は、変更ジャーナル（USN ジャーナル）のあるドライブでだけ記録できます。各フォルダの下に、そのドライブにジャーナルがあるかを表示するようにしました。FAT32、exFAT、ネットワークのフォルダでは、ジャーナルを持てないことを表示します。
- **Web 画面から、ドライブの変更ジャーナルを有効にできます。** ジャーナルのないドライブでは、［変更ジャーナルを有効にする］でジャーナルを作ります。収集サービスまたはエージェントが、`fsutil usn createjournal m=33554432 a=8388608` と同じ操作を行います。
  - 実行の前に確認があり、誰がどのサーバーのどのドライブで有効にしたかを、操作ログに記録します。
  - 有効にできるのは、ジャーナルがないと表示されているドライブだけです。すでにあるジャーナルは変更しません（サイズをほかのソフトが決めている場合があるため）。サイズは固定で、Web 画面からジャーナルを無効にする方法はありません。
  - サーバーで有効にしたい場合のために、同じことをするコマンドも、ドライブ文字を入れた形でコピーできるように表示します。
  - 導入ウィザードでも、「監視フォルダ」の手順で追加したフォルダの下に、同じ表示と［変更ジャーナルを有効にする］を出します。
- **ジャーナルのないドライブを通知します。** 全タブ共通の上部の通知欄（Admin のみ）に、ジャーナルが無効なサーバーとドライブを表示し、選ぶとその監視フォルダの設定を開きます。監視フォルダのページの上部にも同じ通知を出し、ドライブごとのボタンで有効にできます。
- Windows のエージェントでは、1.13.1 から、ジャーナルの状態の表示と［変更ジャーナルを有効にする］に対応します。

### 変更

- **有効にしたジャーナルを 1 分以内に読み始めます。** 収集サービスは、ジャーナルのないドライブを 1 分ごとに確認します（これまでは 10 分ごと）。そのため、管理者が作ったジャーナルを、再起動なしで使い始めます。ドライブの状態は、確認のたびではなく、変わったときにサービスのログに出します。
- **ジャーナルの手順を分かりやすくしました。** [Windows での作成と名前変更](../install.ja.md#windows-での作成と名前変更usn-ジャーナル) に、次の内容を書きました。
  - `fsutil usn queryjournal` の結果の見方
  - `fsutil usn createjournal` の値の意味
  - 実行した後に起きること
  - 注意点（すでにジャーナルのあるドライブでは実行しないこと、無効に戻す方法）
  
  ジャーナルのないドライブについてのログのメッセージと、Web 画面の説明も、同じ内容にそろえました。
- **ReFS に対応していることを明記しました。** 監視、変更ジャーナル、バックアップは、ReFS のドライブでも NTFS と同じく動きます（Windows Server 2025、ReFS 3.14 で確認）。README、インストールの詳細、権限を保てないバックアップ先のエラーに、ReFS を加えました。

### 更新時の注意

- 監視サーバー：ジャーナルの状態を表示するには、更新が必要です。
- Windows のエージェント：そのエージェントのフォルダにも状態と［変更ジャーナルを有効にする］を表示するには、更新が必要です。1.13.0 のエージェントもそのまま動きますが、そのフォルダにはジャーナルの状態を表示しません。
- Linux のエージェントは更新しなくても構いません。
