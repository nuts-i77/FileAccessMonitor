## English

### Highlights

**Collect from several file servers.** Install FileAccessMonitor as an **agent** on other file servers, and their access records come to one monitoring server with one web GUI. A single-server install keeps working as before.

- Agents connect to the monitoring server over HTTPS (port 8443) with a certificate the server creates itself; agents trust exactly that certificate, so no certificate authority is needed. The server never connects to the file servers.
- Register an agent with a one-time code from **Settings → Agents** (valid 24 hours), in the installer or with `FileAccessMonitor.exe enroll`.
- Records wait in an outbox on the agent (up to 2 GB) while the monitoring server is unreachable, and are never saved twice.
- Monitored folders and recording rules are set per server on the monitoring server and sent to the agents. Adding a folder on an agent's server makes that agent check it and set its audit entries; **Unused Files** lists files on the chosen server through its agent.
- A **server** column and filter appear when records come from more than one server; viewing scopes can name a server for each folder.
- The **Agents** list shows last contact, version, waiting batches, and whether file access auditing is on. An agent that has not been in touch for 15 minutes is reported (and again when it is back), and a notice appears when agents run a different version from the monitoring server.

### Other changes

- Notifications can send webhooks through an HTTP proxy (the service runs as SYSTEM, so the Windows proxy setting does not apply).
- Alerts and notifications name the file server the accesses happened on.
- Client machine names for agents' records are resolved on the monitoring server with its reverse-DNS setting.
- The Settings tab is split into **per-server settings** and **settings for all servers**.
- The user details show which servers the user worked on.
- New screenshots in the README; the design document (`DESIGN.html`) is up to date.

### Fixes

- A Word-style save (rename away, then rename in) could be recorded as a deletion when a temporary file was deleted on a reused handle.
- Adding files to a folder could be recorded as a write to the folder when the folder was already gone.
- Development builds reported version 1.0.0 instead of 0.0.0 and could show a false update notice.
- The copy button for the connection string did not work when the GUI was opened over HTTP.
- Stopping the service could take up to 30 seconds while an agent was waiting for work.
- `Agents:Port` in `settings.json` was ignored.

### Upgrading

- Run the new installer on each server; settings and records are kept, and the database is updated on first start.
- **The agent port 8443 opens only once agents are in use.** The first **Issue registration code** turns the feature on; restart the service (`Restart-Service FileAccessMonitor`), open TCP 8443 in the monitoring server's firewall, and issue the code again.
- Keep agents on the same version as the monitoring server.

## 日本語

### 主な変更

**複数のファイルサーバーの記録を 1 か所に集約できるようになりました。** 他のファイルサーバーに FileAccessMonitor を **エージェント** としてインストールすると、そのアクセス記録が 1 台の監視サーバーに集まり、1 つの Web GUI で見られます。1 台構成はこれまでどおり使えます。

- エージェントは HTTPS（ポート 8443）で監視サーバーに接続します。証明書は監視サーバーが自動で作成し、エージェントはその証明書だけを信頼するため、認証局は不要です。監視サーバーからファイルサーバーへは接続しません。
- **設定 → エージェント** で発行する 1 回限りの登録コード（24 時間有効）で、インストーラーまたは `FileAccessMonitor.exe enroll` から登録します。
- 監視サーバーに接続できない間、記録はエージェントの送信待ちフォルダ（最大 2 GB）に残ります。二重に保存されることもありません。
- 監視フォルダと記録ルールは、監視サーバーでサーバーごとに設定し、エージェントに配布します。エージェントのサーバーにフォルダを追加すると、エージェントが存在確認と監査エントリの設定を行います。**未使用ファイル** では、選んだサーバーのファイルをエージェント経由で調べます。
- 複数のサーバーから記録が届くと、**サーバー** の列と絞り込みが表示されます。閲覧範囲もフォルダごとにサーバーを指定できます。
- **エージェント** の一覧に、最終接続、バージョン、送信待ちの件数、ファイルアクセスの監査が有効かを表示します。15 分以上接続がないエージェントを通知し（復旧時も通知）、監視サーバーとバージョンが違うエージェントがあれば画面上部でお知らせします。

### その他の変更

- 通知の Webhook を HTTP プロキシ経由で送れるようになりました（サービスは SYSTEM で動くため、Windows のプロキシ設定は使われません）。
- アラートや通知に、アクセスが発生したファイルサーバー名が入ります。
- エージェントの記録の接続元端末名は、監視サーバーの逆引き DNS 設定で解決します。
- 設定タブを **サーバーごとの設定** と **全体の設定** に分けました。
- ユーザーの詳細で、どのサーバーを使ったかが分かります。
- README のスクリーンショットを更新し、設計書（`DESIGN.html`）を最新にしました。

### 修正

- Word と同じ手順の保存（別名への変更と元の名前への変更）で、一時ファイルの削除が使い回されたハンドルに当たると、文書が「削除」と記録されることがありました。
- フォルダがすでに消えている場合、そのフォルダへのファイル追加が「フォルダへの書込」として記録されることがありました。
- 開発ビルドの版番号が 0.0.0 ではなく 1.0.0 になり、誤った更新のお知らせが出ることがありました。
- Web GUI を HTTP で開いていると、接続文字列のコピーボタンが効きませんでした。
- エージェントが指示を待っている間、サービスの停止に最大 30 秒かかっていました。
- `settings.json` の `Agents:Port` が無視されていました。

### 更新時の注意

- 各サーバーで新しいインストーラーを実行してください。設定と記録は引き継がれ、データベースは初回起動時に自動で更新されます。
- **エージェント用ポート 8443 は、エージェントを使うときだけ開きます。** 初めて **登録コードを発行** を押すと機能が有効になるので、サービスを再起動（`Restart-Service FileAccessMonitor`）し、監視サーバーのファイアウォールで TCP 8443 を開けてから、もう一度コードを発行してください。
- エージェントは監視サーバーと同じバージョンにそろえてください。
