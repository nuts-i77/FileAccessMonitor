## English

### Highlights

**Linux file servers (Samba).** A new Linux agent sends the file accesses of a Samba file server to the monitoring server, next to your Windows file servers.

- It reads the audit lines of Samba's `full_audit` module from the systemd journal: reads, writes, renames and deletions through SMB shares, with the user, client IP address and client machine name.
- Adding a folder on the **Settings** tab (for example `/srv/share/docs`) turns on auditing for the Samba shares that hold it: the agent edits `smb.conf`, checks it with `testparm`, keeps a backup and reloads Samba. **Stop monitoring + remove SACL** restores the share's settings.
- **Unused Files** lists files on the Linux server through its agent.
- Install: download `FileAccessMonitor-1.7.0-linux-x64.tar.gz`, unpack it and run `sudo sh install.sh <connection string>`. See "Linux file servers (Samba agent)" in the README.
- Tested on Ubuntu 24.04 (Samba 4.19) and Rocky Linux 9.4 (Samba 4.23). x86-64 only.

### Other changes

- The **Agents** list shows whether each agent runs on Windows or Linux, with the OS name. The **Audit policy** column is now **Auditing**, since on Linux it means Samba auditing.
- Linux paths are handled case-sensitively in viewing scopes, folder names and unused-file listings.
- New notifications for gaps on Linux servers: journald dropped audit lines, or the journal no longer had the entries from where the agent stopped.

### Upgrading

- Upgrade the monitoring server to 1.7.0 before adding Linux agents; earlier versions do not understand their paths and messages.
- Windows agents work with 1.7.0 as before; upgrade them so their version matches the monitoring server's.

## 日本語

### 主な変更

**Linux のファイルサーバー（Samba）に対応しました。** 新しい Linux 版エージェントで、Samba のファイルサーバーのアクセス記録を、Windows のファイルサーバーと並べて監視サーバーに集められます。

- Samba の `full_audit` モジュールが出す監査ログを systemd のジャーナルから読みます。SMB 共有経由の読み取り・書き込み・名前変更・削除を、ユーザー、接続元の IP アドレス、端末名と一緒に記録します。
- **設定** タブで監視フォルダ（例: `/srv/share/docs`）を追加すると、そのフォルダを含む Samba の共有で監査を有効にします。エージェントが `smb.conf` を書き換え、`testparm` で確認し、バックアップを残して Samba に読み込み直させます。**監視停止 ＋ SACL も削除** で共有の設定は元に戻ります。
- **未使用ファイル** では、Linux のサーバーのファイルをエージェント経由で調べます。
- 導入: `FileAccessMonitor-1.7.0-linux-x64.tar.gz` をダウンロードして展開し、`sudo sh install.sh <接続文字列>` を実行します。詳しくは README の「Linux のファイルサーバー（Samba エージェント）」を参照してください。
- Ubuntu 24.04（Samba 4.19）と Rocky Linux 9.4（Samba 4.23）で確認しています。x86-64 のみです。

### その他の変更

- **エージェント** の一覧に、Windows か Linux かと OS 名を表示します。Linux では Samba の監査を指すので、**監査ポリシー** の列名を **監査** に変えました。
- 閲覧範囲、フォルダ名、未使用ファイルで、Linux のパスを大文字と小文字を区別して扱います。
- Linux のサーバーで記録が途切れたときの通知を追加しました（journald が監査ログを捨てた場合、エージェントが止まった時点からの記録がジャーナルに残っていなかった場合）。

### 更新時の注意

- Linux 版エージェントを追加する前に、監視サーバーを 1.7.0 に更新してください。以前の版は Linux のパスやメッセージを正しく扱えません。
- Windows 版エージェントはこれまでどおり動きます。監視サーバーとバージョンをそろえるため、更新してください。
