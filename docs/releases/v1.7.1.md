## English

### Fixes

- Upgrading a monitoring server that already had the **File Access Monitor** firewall rule (added by v1.6.0 or later) stopped with "Failed to register or start the service (exit code 1)", and the service was left stopped. The installer now updates the rule correctly, and a problem with the firewall rule no longer keeps the service from starting.

### Upgrading

- If an upgrade to v1.6.x or v1.7.0 showed that message, the new files are in place; start the service (`Start-Service FileAccessMonitor`) or run the v1.7.1 installer.
- Linux agents are unchanged; v1.7.0 agents work with a v1.7.1 monitoring server. See [v1.7.0](https://github.com/nuts-i77/FileAccessMonitor/releases/tag/v1.7.0) for the changes in 1.7.

## 日本語

### 修正

- **File Access Monitor** のファイアウォール規則（v1.6.0 以降で追加されたもの）がある監視サーバーを更新すると、「サービスの登録または起動に失敗しました (終了コード 1)」と表示され、サービスが停止したままになりました。インストーラーが規則を正しく更新するように直し、ファイアウォール規則の処理に失敗してもサービスは起動するようにしました。

### 更新時の注意

- v1.6.x や v1.7.0 への更新でこのメッセージが出た場合、新しいファイルは入っています。サービスを起動する（`Start-Service FileAccessMonitor`）か、v1.7.1 のインストーラーを実行してください。
- Linux 版エージェントに変更はありません。v1.7.0 のエージェントは v1.7.1 の監視サーバーとそのまま使えます。1.7 の変更内容は [v1.7.0](https://github.com/nuts-i77/FileAccessMonitor/releases/tag/v1.7.0) を参照してください。
