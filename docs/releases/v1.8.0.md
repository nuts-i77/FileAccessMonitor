## English

### Highlights

**The monitoring server runs on Linux.** The web GUI, database, notifications and agent port now also run on x86-64 Linux with systemd. Install the package for your distribution:

```sh
sudo dnf install ./fileaccessmonitor-server-1.8.0-1.x86_64.rpm   # or: sudo apt install ./fileaccessmonitor-server_1.8.0-1_amd64.deb
fileaccessmonitor-server                        # monitoring only to start with; shows the mode and port
sudo fileaccessmonitor-server --collect         # also record this machine's Samba accesses (runs as root)
```

Windows and Linux agents connect to it as they do to a Windows monitoring server. See "Monitoring server on Linux" in the README.

**Monitoring server only.** A monitoring server can now leave out its own accesses and only show what agents send, on Windows too. The installer has a new choice, **Monitoring server only**: it does not read the Security log, change the audit policy or set SACLs on that machine, and the machine is not listed as a file server. Switch an existing install with `FileAccessMonitor.exe local-collection off` (or `on`) and a service restart; **Settings → App info** shows the mode.

### Other changes

- **deb and rpm packages** for the Linux agent and monitoring server (`fileaccessmonitor-agent`, `fileaccessmonitor-server`), so they install, upgrade and uninstall with apt or dnf. The tar.gz files remain for other distributions and are now named `-linux-x64-agent` and `-linux-x64-server`.
- A machine runs either the monitoring server or the agent: the packages conflict (installing one replaces the other), and the tar.gz installers refuse to install next to the other.

### Upgrading

- Windows: run the new installer; existing installs keep recording accesses on the server as before.
- Linux agents from 1.7 work with a 1.8 monitoring server; upgrade them so their version matches. To move a 1.7 agent to the package, run `sudo sh install.sh --uninstall` in its 1.7 folder, then install the package: the registration is kept, so it connects again without a new code.

## 日本語

### 主な変更

**監視サーバーが Linux でも動くようになりました。** Web GUI、データベース、通知、エージェント用ポートが、systemd の動く x86-64 の Linux でも動きます。ディストリビューションに合ったパッケージで導入します。

```sh
sudo dnf install ./fileaccessmonitor-server-1.8.0-1.x86_64.rpm   # または: sudo apt install ./fileaccessmonitor-server_1.8.0-1_amd64.deb
fileaccessmonitor-server                        # 最初は監視専用。モードとポートを表示
sudo fileaccessmonitor-server --collect         # このマシンの Samba のアクセスも記録（root で動きます）
```

Windows 版・Linux 版のエージェントは、Windows の監視サーバーと同じように接続できます。詳しくは README の「Linux の監視サーバー」を参照してください。

**監視サーバーのみ（監視専用）にできるようになりました。** Windows でも、監視サーバー自身のアクセスは記録せず、エージェントから届いた記録だけを表示できます。インストーラーに **監視サーバーのみ** を追加しました。この場合、そのマシンのセキュリティログは読まず、監査ポリシーや SACL も変更せず、ファイルサーバーの一覧にも出しません。インストール済みの環境は `FileAccessMonitor.exe local-collection off`（または `on`）を実行してサービスを再起動すると切り替わります。今の状態は **設定 → アプリ情報** に表示されます。

### その他の変更

- Linux のエージェントと監視サーバーの **deb / rpm パッケージ**（`fileaccessmonitor-agent`、`fileaccessmonitor-server`）を用意しました。apt や dnf で導入・更新・削除できます。他のディストリビューション向けの tar.gz も残し、名前を `-linux-x64-agent` / `-linux-x64-server` に変えました。
- 1 台のマシンには、監視サーバーとエージェントのどちらか一方だけを入れます。パッケージ同士は衝突として扱われ（一方を入れるともう一方は置き換えられます）、tar.gz のインストーラーは、もう一方が入っている場合は導入しません。

### 更新時の注意

- Windows: 新しいインストーラーを実行してください。既存の環境は、これまでどおりサーバー自身のアクセスも記録します。
- 1.7 の Linux エージェントは 1.8 の監視サーバーとそのまま使えます。バージョンをそろえるため、更新してください。1.7 のエージェントをパッケージに切り替えるには、1.7 を展開したフォルダで `sudo sh install.sh --uninstall` を実行してからパッケージを入れます。登録は残るので、登録コードなしで接続し直します。
